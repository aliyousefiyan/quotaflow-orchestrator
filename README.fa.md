# QuotaFlow Orchestrator — راهنمای فارسی

این پروژه یک کنترل‌کننده مستقل و کم‌هزینه برای **توزیع اجرای کارهای قطعی بین چند مخزن GitHub Actions با مالکیت‌های جداگانه** است.

**مهم:** سهمیه Actions به **مالک مخزن** تعلق می‌گیرد، نه کاربری که دکمه Run را زده است. برای بهره‌گیری از ظرفیت سه حساب مجاز، باید سه مخزن اجرایی مستقل و متعلق به همان حساب‌ها داشته باشیم. انتقال غیرمجاز داده یا تلاش برای دور زدن مقررات سرویس مجاز نیست.

## کارهایی که نسخه فعلی انجام می‌دهد

- ثبت کار در صف SQLite با شناسه و ورودی تغییرناپذیر؛ تکرار ثبت کار، آن را دوباره اجرا نمی‌کند.
- اولویت‌بندی و بررسی ظرفیت واقعی ثبت‌شده هر حساب؛ برای اطلاعات نامعلوم یا قدیمی‌تر از ۱۲ ساعت اجرای هزینه‌دار ممنوع است.
- انتخاب مالک مناسب بر اساس سهمیه و رزرو اضطراری؛ حداکثر یک کار فعال در هر حساب.
- تأیید هویت مالک حساب GitHub، مالکیت مخزن، معتبر بودن Workflow و قرارداد Worker.
- اجرای **حداکثر یک** کار با تأیید صریح `--approve-dispatch`؛ پیگیری نتیجه با `sync`.
- جلوگیری از ارسال مجدد خودکار در صورت قطع شبکه بعد از درخواست، تا هزینه دوبرابر ایجاد نشود.
- امکان اجرای تست‌های خود نرم‌افزار بدون Work و Codex و بدون کلید API.

## نصب و آزمایش

```bash
python -m unittest discover -s tests -t . -v
python -m quotaflow --config examples/accounts.example.json --budgets examples/budgets.unknown.json --state demo.sqlite3 enqueue --file examples/jobs.example.json
python -m quotaflow --config examples/accounts.example.json --budgets examples/budgets.unknown.json --state demo.sqlite3 plan
```

برای اتصال واقعی، فایل الگو را به `accounts.json` و `budgets.json` کپی کنید، نام مالک و مخازن خود را وارد کنید و برای هر حساب توکن مجاز را **فقط در متغیر محیطی** نگهدارید. دستور `doctor` تأیید دسترسی را انجام می‌دهد؛ اجرای واقعی صرفاً با `dispatch --approve-dispatch` انجام می‌شود.

## ارتباط با Codex و Work

این دو قابلیت سهمیه مشترک OpenAI دارند و به صورت خودکار قابل افزایش با استفاده از سه حساب GitHub نیستند. برنامه‌های بک‌تست و اسکریپت‌های آماده می‌توانند در Actions مستقل اجرا شوند؛ ولی تولید کد جدید با هوش مصنوعی همچنان تابع سهمیه Work/Codex است. پنجره‌های سهمیه Codex را می‌توان با `python -m quotaflow codex-limits` از رابط رسمی محلی خواند. اما اعتبار مشترک ماهانه Work/Codex را نمی‌توان از این درصدها نتیجه گرفت و باید جداگانه تأیید شود. برنامه `ai-plan` از شروع کار AI بدون اعتبار قابل تأیید جلوگیری می‌کند. هیچ عدد ساختگی به سیستم داده نمی‌شود.

## وضعیت انتشار

نسخه 0.4.1 یک **پروژه متن‌باز قابل تست و توزیع** است. اتصال عملی سه Worker، اجرای خودکار بدون دخالت اپراتور و استفاده در پروژه‌های معاملاتی فعال هنوز انجام نشده و به بررسی مستقل دسترسی‌ها، سهمیه‌ها، نسخه‌های فعال و امنیت نیاز دارد. کد برای معاملات واقعی یا ارسال سفارش طراحی نشده است.


### اجرای آزمایشی بدون توکن شخصی

در مخزن عمومی می‌توان با اجازه صریح `github_actions_self_token: true` و `GITHUB_TOKEN` محدود همان مخزن، یک Workflow ایمن را به همان مخزن ارسال کرد. این مجوز برای مخازن خصوصی یا ارسال به حساب دیگر معتبر نیست. آزمون واقعی مسیر صف SQLite تا Worker در فایل `.github/workflows/controller-queue-e2e.yml` قرار دارد. برای سه حساب خصوصی، همچنان سهمیه واقعی و احراز هویت مستقل هر مالک لازم است.


## طرح دو حساب Gmail و Yahoo به‌عنوان ذخیره آخر

ماژول هشدار نسخه 0.4 با نگاشت دقیق دو حساب در یک Gmail، دریافت رویداد HMAC از Issue خصوصی، ذخیره توقف حساب در SQLite، انتخاب اولویت حساب اول → دوم → Yahoo و کنترل بودجه جدید ساخته شده است. **نصب Google Apps Script و صدور مجوزهای خصوصی هنوز نیازمند اقدام صاحب حساب است.** دستور کامل و امن در [راهنمای فارسی Gmail](integrations/google_apps_script/README.fa.md) آمده است. با نبود تأیید سلامت منبع ایمیل در ۶۰ دقیقه اخیر، مسیر خصوصی خودکار مسدود می‌شود.


### نکته امنیتی Google Apps Script

نسخه Gmail کم‌دسترسی از `gmail.readonly` استفاده می‌کند و در دو فایل مستقل [Code.gs](integrations/google_apps_script/Code.gs) و [appsscript.json](integrations/google_apps_script/appsscript.json) ارائه می‌شود. باید هر دو را در پروژه Google تنظیم کنید؛ کد قبلی GmailApp درخواست دسترسی کامل به ایمیل داشت و **نباید** مجوز آن را تأیید کرد.
