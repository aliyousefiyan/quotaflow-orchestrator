# سیاست مالکیت ثابت پروژه‌ها — QuotaFlow

**اصل:** هر پروژه یک **حساب GitHub مرجع** و در حالت مطلوب یک **مخزن مستقل** دارد. کد منبع، داده‌های خام، نتایج بک‌تست، لاگ و سند تحویل همان پروژه باید به حساب مرجع آن ارجاع شوند. «Worker محاسباتی» با «مالک مرجع پروژه» متفاوت است.

## تصمیم‌های اصلی
- برای هر پروژه فقط یک `home_account` تعریف می‌شود؛ هر چت موظف است ابتدا فایل فهرست حساب‌ها و سپس سند اختصاصی همان پروژه را بخواند.
- **مسیر پروژه با نام یک شاخه یا نام مشابه مخزن تعیین نمی‌شود.** محتوای GitHub، handoff محلی، مسیر فعال و وابستگی‌ها باید تأیید شوند.
- اگر `status=proposed_home` باشد، پروژه **اجازه اجرای خصوصی از طریق QuotaFlow ندارد** تا محل منبع/داده و مالک واقعی تأیید شود.
- مالکیت پروژه صرفاً برای استفاده از سهمیه تغییر نمی‌کند. در صورت کمبود ظرفیت، اجرای **مستقل، استاندارد و بدون داده محرمانه** می‌تواند فقط برای پروفایل‌های محدود `smoke` و `sample_compute` در Worker دیگری انجام شود، آن هم با تأیید منبع، هویت، بودجه و `--approve-dispatch`. خروجی باید زیر نام پروژه اصلی ثبت شود و انتقال خصوصی خودکار ممنوع است.
- Yahoo به‌عنوان آخرین **حساب محاسباتی پشتیبان** باقی می‌ماند؛ از آن نباید برای مخفی‌کردن نام پروژه، ساخت چند نسخه نامعلوم یا دورزدن مقررات GitHub استفاده شود.
- تا وقتی پروژه‌های قدیمی در چند مخزن موجود باشند، فقط یک مرجع `verified_repository` مشخص می‌کنیم و سایر کپی‌ها را `legacy/archive` (بدون پاک‌سازی) علامت می‌زنیم. جابه‌جایی داده فقط پس از ممیزی SHA، آزمایش parity و تایید مسیر فعال انجام شود.
- `--project-registry` اختیاری است؛ بدون آن نرم‌افزار عمومی همچنان رفتار نسخه قبلی را دارد، اما در استفاده شخصی باید آن را اجباری در فرمان‌های واقعی لحاظ کنیم. ربات نمی‌تواند به‌صورت مستقل از همهٔ چت‌ها مسیر جدید بسازد.

## بازنشانی ماه میلادی

در ساعت **۰۰:۰۰ UTC روز اول ماه میلادی**، هشدار HOLD ماه قبل دیگر `account_hold` موثر نیست؛ اما در SQLite برای ممیزی باقی می‌ماند. هشدار ایمیل قدیمی که با تأخیر وارد شده نیز نمی‌تواند ماه جدید را مسدود کند. از طرف مقابل، اگر `budgets.json` مربوط به ماه قبل باشد، حتی اگر چند دقیقه پیش ثبت شده باشد، **برای هزینه جدید غیرقابل‌استفاده** است. بودجه جدید باید با رقم واقعی، واحد USD یا تبدیل معتبر، مالک مربوطه و timestamp جدید تایید شود. اگر رقم نامشخص است کار هزینه‌دار مسدود می‌شود.

## استفاده

فایل private registry مطابق [الگوی عمومی](../examples/project_registry.example.json) تهیه و فقط در فضای خصوصی نگهداری شود. شناسه‌های `home_account` باید دقیقاً با شناسه‌های `accounts.json` همخوانی داشته باشند؛ نام نمایشی یا آدرس ایمیل به‌تنهایی کافی نیست.

```bash
python -m quotaflow --config accounts.json --budgets budgets.json --project-registry project_registry.json project-home --project EMA
python -m quotaflow --config accounts.json --budgets budgets.json --project-registry project_registry.json plan
```

برای اجرای کاری در حساب دیگر، ابتدا ثابت کنید که `portable_profiles` شامل پروفایل موردنظر است، هدف همان نوع کار مستقل است و هیچ داده یا سورس خصوصی بدون مجوز جابه‌جا نشده؛ سپس تایید واقعی بودجه، هویت مخزن و worker برقرار باشد.

## نکته مهم برای محیط ویندوز

پیش از دسترسی به فایل پروژه‌های قبلی، ابتدا `D:\Projects\START_HERE_PROJECT_CHATS.md` و بعد `PROJECT_CHAT_HANDOFF.md` و `FILE_LOCATIONS_20261101.csv` پروژه مربوطه را بخوانید. مسیرهای فعال و جابه‌جا نشده را هم بررسی کنید. هیچ آرشیو ZIP را به جای نسخه فعال سرور فرض نکنید.
