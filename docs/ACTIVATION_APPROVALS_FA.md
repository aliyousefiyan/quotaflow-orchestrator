# راهنمای فعال‌سازی ایمن QuotaFlow — تأییدیه‌های موردنیاز

وضعیت: **آماده دریافت تأییدیه‌های مالک حساب؛ اجرای خصوصی هنوز مجاز نشده است** (۱۲ نوامبر ۲۰۲۶).

این راهنما عمومی است و **نام مخازن خصوصی، توکن‌ها، موجودی واقعی حساب‌ها یا داده‌های معاملاتی** را ثبت نمی‌کند.

## آنچه همین حالا تأیید شده است
- نسخه 0.3.0 روی مخزن عمومی منتشر شده؛ تست‌های CI و آزمایش انتهابه‌انتهای SQLite → کنترل‌کننده → GitHub Actions Worker موفق شده‌اند.
- Workflow نمونه فقط `workflow_dispatch`، `smoke` و `sample_compute` دارد؛ سفارش، SSH، اسکریپت دلخواه و داده خصوصی را نمی‌پذیرد.
- مسیر خودمخزنی عمومی از `GITHUB_TOKEN` کوتاه‌مدت GitHub استفاده می‌کند؛ برای آن PAT شخصی لازم نیست.
- سه Worker خصوصی جداگانه در مخازن مجاز نصب شده‌اند، اما هنوز **هیچ تأییدیهٔ مصرف بودجه خصوصی یا اجرای خودکار بین حساب‌ها** صادر نشده است.

## ۱. تأیید مالک و سهمیه — تکرار برای هر سه حساب

1. مستقیماً در مرورگر وارد **همان حساب GitHub مالک مخزن مربوطه** شوید؛ صرف اتصال حساب به ChatGPT، مجوز خواندن صورتحساب را تضمین نمی‌کند.
2. مسیر [GitHub Billing & Licensing](https://github.com/settings/billing) را باز کنید. بخش‌های Usage و Budgets and alerts را بررسی کنید.
3. مقادیر را به‌صورت غیرمحرمانه ثبت کنید: **واحد بودجه (USD/دقیقه)، اعتبار مشمول برنامه، مصرف‌شده، باقی‌مانده قابل‌خرج، تاریخ/زمان مشاهده به UTC، بازنشانی دوره**. داده‌های Usage ممکن است با تأخیر ثبت شوند. «دقایق باقیمانده» را بدون نرخ واقعی و اطلاعات برنامه به دلار تبدیل نکنید.
4. برای Actions یک سقف هزینه مورد توافق تعیین کنید، اعلان‌های مصرف ۹۰ و ۱۰۰ درصد ظرفیت مشمول را فعال کنید و در صورت وجود، گزینه **Stop usage when budget limit is reached** را برای جلوگیری از هزینه ناخواسته بررسی و روشن کنید. صرفاً دریافت هشدار به معنی توقف واقعی نیست.
5. پیش از هر اجرای خصوصی، بودجه واقعاً قابل‌خرج و زمان مشاهده را برای مالک مربوطه در فایل `budgets.json` **فقط روی دستگاه کنترل‌کننده** بنویسید. فایل‌های حساب و بودجه به Git عمومی، Issue، لاگ یا چت همراه با کلید منتقل نشوند. داده قدیمی‌تر از ۱۲ ساعت طبق سیاست فعلی مسدود می‌شود.

**جایگزین بدون API:** برای شروع، ارائه اعداد قابل‌تأیید از صفحه Billing توسط صاحب هر حساب کافی است. نیازی نیست کاربر از ابتدا توکن خواندن صورتحساب بسازد.

**گزینه خواندن API (اختیاری):** اگر بخواهید گزارش صورتحساب بدون ورود دستی تهیه شود، برای همان صاحب حساب یک توکن Fine-grained جداگانه با **User account permission: Plan → Read-only** ایجاد کنید. API خواندن Usage ممکن است براساس نوع صورتحساب 403/404 بدهد؛ در آن صورت fallback همان صفحه Billing است. **این توکن، توکن اجرای Worker نیست.**

## ۲. تأیید اجازه اجرای Workflow خصوصی — برای هر حساب

1. در [Fine-grained Personal Access Tokens](https://github.com/settings/personal-access-tokens) با حساب مالک مربوطه، `Generate new token` را بزنید. تاریخ انقضای کوتاه (مثلاً ۳۰ روز) تعیین کنید.
2. **Resource owner** را همان حساب مالک Worker انتخاب کنید و **Only select repositories** را روی *فقط همان مخزن Worker* قرار دهید.
3. در Repository permissions فقط `Actions: Read and write` (و دسترسی‌های پایه خودکار موردنیاز GitHub مانند Metadata read) بدهید؛ از scope جامع `repo` یا دسترسی همه مخازن خودداری کنید. برای API `workflow_dispatch` مجوز `Actions write` لازم است.
4. توکن را فقط در محیط امن خودتان (مانند Windows Credential Manager/Secret Manager یا متغیر محیطی خصوصی فرایند کنترل‌کننده) قرار دهید. **توکن را هرگز در چت، Issue، ریپوی عمومی، اسکرین‌شات یا فایل قابل‌اشتراک قرار ندهید.**
5. در هر مخزن، Workflow موردنظر باید روی شاخه پیش‌فرض GitHub موجود و فعال باشد. در `Settings → Actions → General` تنظیمات مجوز و در `Actions` حضور `QuotaFlow approved worker` را بررسی کنید. برای اجرای دستی `workflow_dispatch` دسترسی write به مخزن لازم است.
6. فقط پس از تأیید بودجه و هویت: برای هر مالک، یک **Smoke** کوچک و بدون داده واقعی به شکل دستی اجرا، Run URL و نتیجه Success را ثبت کنید. تا قبل از تأیید آن، اجرای خودکار چندحسابی خاموش بماند.

## ۳. تأیید سهمیه Codex و Work

- پنجره‌های مصرف **Codex CLI** با `python -m quotaflow codex-limits` به‌صورت فقط‌خواندنی قابل بررسی‌اند.
- این دو پنجره ۵ ساعته/هفتگی لزوماً **موجودی ماهانه مشترک Work/Codex** نیستند.
- اگر حساب در `ChatGPT Desktop → Settings → Usage & billing` موجودی مشترک نشان دهد، فقط *موجودی و بازنشانی* را ثبت کنید؛ در غیر این صورت مقدار `unknown` حفظ شود و پردازش جدید عامل AI خودکار اجرا نشود.
- خود QuotaFlow اساساً **Work/Codex را خودکار اجرا نمی‌کند**؛ برنامه فقط پیشنهاد تقسیم کار و نیاز به تأیید دستی را گزارش می‌دهد.

## ۴. تأیید ایمنی پروژه‌های خصوصی

- هر پروژه معاملات (EMA، Router، M/W، Fusion، Gainer، ATAS و Whale Collector) مستقل است.
- پیش از ورود کد/داده هر پروژه، مسیرهای محلی طبق `START_HERE_PROJECT_CHATS.md`، `PROJECT_CHAT_HANDOFF.md` و `FILE_LOCATIONS_20261101.csv` بررسی شوند.
- نسخه فعال، commit SHA، وابستگی‌ها، هش دیتاست، دامنه دسترسی، اجرای فقط‌آزمایشی و بازگشت‌پذیری ثبت شود.
- مجوز اجرای نمونه `smoke` **به معنی مجوز تغییر کد استراتژی، استقرار، معامله دمو/واقعی، ارسال سفارش، افزایش ریسک یا انتقال دیتاست خصوصی نیست**.

## ۵. دروازه پذیرش/فعال‌سازی

| دروازه | شرط قبولی | وضعیت اولیه |
|---|---|---|
| Public CI و public E2E | تست + Worker success | PASS |
| هویت/Workflow سه مالک | تأیید مالکیت و تطبیق نسخه Worker | PASS (فقط خواندنی) |
| Billing سه مالک | اعداد واقعی و سقف هزینه هر حساب | **PENDING** |
| اختیار مصرف خصوصی | رضایت صریح مالک + توکن کم‌دسترسی خصوصی | **PENDING** |
| آزمایش خصوصی حساب‌ها | ۳ اجرای `smoke` با Run URL معتبر | **PENDING** |
| اتصال بک‌تست واقعی | بررسی مستقل منبع/داده/ریسک | **NOT AUTHORIZED** |
| سهمیه Work/Codex | ارزیابی جدا؛ نداشتن عدد معتبر → عدم اجرای AI | اختیاری/unknown |

پس از پرشدن دروازه‌های خصوصی، اپراتور با `doctor` و `plan` مطمئن می‌شود که مالک/Workflow و بودجه برقرارند و سپس **یک کار در هر بار** با `dispatch --approve-dispatch` ارسال و با `sync` تطبیق داده می‌شود. برای کارهای مبهم، تکرار خودکار ممنوع است.

## کارهایی که صاحب حساب باید به‌طور صریح تأیید کند

- [ ] محدودیت هزینه خصوصی هر سه مالک مشخص است؛ هزینه اضافه بر بودجه **اجازه ندارد** مگر با دستور مستقل.
- [ ] برای هر مالک، **صرفاً Worker آزمایشی** مجاز است و Secret اختصاصی در فضای امن نگهداری می‌شود.
- [ ] نمونه `smoke` حداکثر ۵ دقیقه با دسترسی فقط‌خواندنی، بدون معاملات و بدون داده خصوصی را مجاز می‌دانم.
- [ ] تنها پس از دریافت Success هر سه، بررسی‌های بیشتر انجام شود؛ بک‌تست واقعی و استقرار نیازمند تأیید جداگانه است.
